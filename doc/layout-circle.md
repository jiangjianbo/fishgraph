# 布局设计说明：圆形布局（circle）

> 注册名 `'circle'`，实现于 `src/layout/circle/strategy.ts`（单文件，约 115 行）。
> 定位有二：一个真正可用的「分量环」布局；更重要的是**验证架构策略接缝的
> 最小反例**——一个无力学、无迭代的算法必须也能完整实现 `LayoutStrategy`，
> 以此证明接缝没有隐藏的力学假设（架构 §7 影响点 3）。

## 1. 算法设计

把每个**连通分量**摆成一个正多边形环，多个分量沿大环排开、互不重叠：

1. BFS 求连通分量；
2. 分量内部：成员均匀分布在半径 `r = L × max(2, √n) / 2` 的圆上
   （n = 成员数）。半径按 √n 缩放，使圆周上相邻节点的**弧间距**与
   `naturalLength` 同量级——与力导向共享同一把表面间距标尺；
3. 多分量：分量中心沿半径 `orbitRadius` 的大环排开，
   `orbitRadius = maxDiameter × 分量数 / 2π + L`，
   其中 `maxDiameter` 取各分量直径估算值的最大者——保证任意两个分量环
   不相交，外围再留一个 L 的间隙。

对环上相邻节点恰好由一条边相连的图（纯环图），该布局即是它的自然嵌入；
对一般图，它提供确定、整洁、无重叠的排布。

## 2. 生命周期实现（接缝的最小满足）

`LayoutStrategy` 的每个成员在「构造即完成」语义下的平凡实现：

| 接口成员 | 实现 | 说明 |
|---|---|---|
| `step()` | 恒返回 `false` | 无可接受的移动，动画帧自然停止 |
| `run()` | 立即返回 `{ iterations: 0, converged: true, energy: 0 }` | 构造函数里已摆好 |
| `energy` / `iterations` / `energyHistory` | `0` / `0` / `[]` | 接口约定「无能量概念的策略返回 0」 |
| `converged` / `stage` | `true` / `3` | 语义上处于最终状态 |
| `refresh(options)` | 仅当 `naturalLength` 或 `seed` 变化时重新 `place()` | 参数里只有这两项影响它 |
| `invalidate()` | 空 | 无力学：外部挪动节点后无需重算 |
| `rebuild()` | 重新 `place()` | 图结构变化后重摆 |
| `forceSnapshot` | 不实现 | 可选方法；门面对不支持的策略抛错 |

`place()` 统一尊重 `placed` 标记：用户显式定位的节点不动（与力导向的初值
约定一致，数据来自 `GraphStore`）。

## 3. 参数依赖

只消费两个布局选项：

- `naturalLength`：环半径与分量间距的长度标尺；
- `seed`：当前实现未使用随机性（预留；将来加抖动破对称时无需改接口）。

其余力学选项（交叉、跳数、引力模式……）对它全部无意义——这正是接缝
「按名创建 + 策略自行解释选项」的价值：`LayoutOptions` 是公共超集，
算法只取所需。

## 4. 与架构的关系

- **不做坐标系修正、不做组约束**：hub 被当作普通节点摆上环。分组语义
  （包含、聚集）是力导向的解释，circle 不解释（架构决策 5 的「解释角色
  是各算法自己的事」）；
- **热切换示范**：`strategy.test.ts` 用它验证 `algorithm` 选项直接选用、
  `setStrategy` 运行时切换（图数据保留、位置重新初始化）、切回力导向后
  仍能弛豫到合法布局——circle 是切换实验的「另一极」。

## 5. 验证

- `strategy.test.ts`：「algorithm 选项直接选用策略：circle 无迭代、立即收敛、
  节点成环」；「setStrategy 热切换」两条用例；
- `architecture.test.ts`：单文件实现同样遵守「src/ 不含图实例数据」边界。

## 6. 已知边界

- 不处理分量环与显式定位节点可能的重叠（显式定位节点被视为锚，环的半径
  估算不含它）；需要严格不重叠时，可组合 `coordinateSystem: 'grid'` 在
  布局后吸附（坐标系与算法正交，架构 §7 影响点 6）；
- 无标签感知：不问节点文字大小（力导向的阶段 3 概念对它不存在）。
