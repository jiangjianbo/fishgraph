# 布局设计说明：力导向无向图（force-undirected）

> 注册名 `'force-undirected'`，实现于 `src/layout/force-undirected/`，
> 是**基础算法**：除本算法的 `coarse.ts`（粗布局）与 `strategy.ts`
> （流水线编排）外，共享力学引擎件也在此目录——`forces.ts`（力场）、
> `solver.ts`（弛豫求解器）、`hops.ts`（跳数矩阵）、`crossings.ts`
> （交叉计数）、`quadtree.ts`（BH 四叉树）、`spatialgrid.ts`（空间网格，
> 均自原 `force/` 迁入）。有向派生算法 `force-directed` 通过本算法预留的
> 派生接缝复用全部流程与引擎（见 §9）；分组派生 `force-group` 已随旧
> `force/` 一并移除，待重写。
> 实现 `doc/布局核心原则.md` 无向图流水线的后三个阶段：
> **质点网格粗布局 → 膨胀压实 → 连续坐标微调**（第一阶段的「长尾卷起/图粗化」
> 暂不实现）。

## 1. 设计动机

纯力导向从随机/BFS 初值开始弛豫，大图收敛慢、初值偶然性大。无向图流水线
的思路是：**布局的大部分工作在离散阶段就完成**——先用质点网格把拓扑骨架
摆对（邻居相邻、环紧凑、无重叠），再让力学引擎做一小段「抛光」。由此：

- **无重叠由构造保证**，不依赖弛豫兜底；
- **环/树等结构在粗布局阶段就消灭长边穿透**（邻居总是贴邻放置）；
- **弛豫步数大幅减少**（收敛自适应，实测几十至两千余步，
  force-directed 同类图常需上万步预算）。

## 2. 阶段 2：质点网格粗布局（coarse.ts）

所有节点一律视为 **1×1 无面积质点**：碰撞检查退化为格子占用查询，
布置在整数格上。

### 2.1 度数优先的连通生长

放置顺序不是纯度数排序，而是 **Prim 式候选集生长**：

1. 种子 = 全局度数最高者（平局按下标序），放格 (0,0)；
2. 维护候选集 = 「已放置节点的未放置邻居」；每步从候选集中取度数
   最高者放置；
3. 候选集耗尽 → 剩余节点取度数最高者作为新分量种子（孤儿放置），
   贴已放置区域右边缘外侧。

> 为什么不用纯度数降序：树 21 中分支节点（度 5）会先于 root（度 4）
> 放置，四个分支先横排成一条线，root 后放导致骨架断裂、长边穿透
> （实测 8 条交叉边）。连通生长保证每个节点放置时都有已放置邻居可贴近。

### 2.2 放置评分

候选节点以已放置邻居的格坐标均值为中心**环形扩搜**（半径上限 5 格），
逐格评分择优：

```text
score = 张力项 − RING_BONUS × 环周长项

张力项   = Σ 到全部已放置邻居的曼哈顿距离   （连线像橡皮筋拉向邻居）
环周长项 = 与候选格 8 邻接、且图上相邻的已放置邻居对数
           （把节点拉进邻居的"夹角"里，三角形环的周长 3 格接近下限）
```

已达理论最优（全部邻居贴邻，`score ≤ 邻居数`）提前收工；扩搜 3 环后
有解即停。**确定性**：环扩展次序、平局规则全部固定，同输入逐位复现。

### 2.3 死锁机制（插行列）

候选点周围被完全占满（无向默认判定：搜索预算内没有空格，或最佳空格
张力 > `2×邻居数 + 2`）时，不做无效搜索，直接触发 `insertLine`：
在锚点的某一侧**整体插入一行/列**，把该侧已放置节点全部推开一格，挤出
新空格。方向取需要移动的占用格最少的一侧（平局按 +x/−x/+y/−y 固定序），
挤出的新格就是锚点格本身（锚点的占用者总被移走）。放置因此 **100%
不死锁**（星形 K1,12 等高密度结构有用例覆盖）。

「什么算死锁」与「死锁了怎么办」都是 `CoarseHeuristics` 钩子
（`isDeadlock` / `deadlock`），由具体算法定义——有向算法把判定改写为
「最佳候选偏离层级行超过容忍行数」（见 [layout-force-directed.md](./layout-force-directed.md)）。

## 3. 阶段 3：膨胀压实 + 变距映射

质点网格坐标不含真实尺寸，直接 × L 映射会重叠。压实阶段：

1. **删空行空列**：收集占用行/列（推箱子式消灭大片空白）；
2. **变距拉伸**：相邻占用行（列）的物理间距 = 两侧该行（列）最大
   包围半径和 + `0.3 × naturalLength` 间隙。任意两个节点的中心距
   因此不小于「半径和 + 间隙」——无重叠由构造保证；
3. **写回**：网格坐标映射为连续坐标写入 `x/y`；整体平移使质心位于
   原点（有 `placed` 节点时改为对齐 placed 均值，且 placed 节点
   不移动——其占格在放置开始前已从连续坐标反算）。

## 4. 阶段 4：连续坐标微调（共享力学引擎）

粗布局的全部产物就是一组连续坐标初值。微调阶段直接使用本目录的
力学引擎（自原 `force/` 迁入的基础引擎件），新算法不重新实现任何力学：

| 引擎件 | 位置 | 用途 |
|---|---|---|
| `RelaxationSolver` | 本目录 `solver.ts` | 信任域 + 回溯线搜索弛豫 |
| `computeForcesExact / BH` | 本目录 `forces.ts` | 力场全栈（橡皮筋、跳数衰减斥力、避让、交叉罚、文字） |
| `deriveParams` | 本目录 `forces.ts` | 从 `LayoutOptions` 派生物理参数 |
| `buildHopScale` | 本目录 `hops.ts` | 跳数斥力衰减矩阵 |
| `createCoordinateSystem` | `layout/coordinates.ts` | 布局后坐标系修正（free/grid） |

`force-directed` 派生策略同样从本目录导入引擎件——引擎归基础算法
所有，策略只是消费者。

策略自组装 `ForceContext`：`stage` 恒为 3（全量力场，分阶段弛豫的
职责已由粗布局承担）、`extensions` 为空（不消费组约束）、
`edgeKaMul`/`edgeCrossCounts` 常规初始化。迁移只移动文件与 import，
引擎行为零改动。

迭代预算的安全网 `DEFAULT_MAX_ITERATIONS = 4000`（正常路径由收敛判据
自适应提前停）。实测收敛步数：

| 图 | 收敛步数 | 备注 |
|---|---|---|
| n=200 随机图 | ~80 | |
| 树 21 | ~470 | |
| n=500 随机图 | ~380 | |
| n=2000 随机图 | ~1540 | |
| mermaid 样本 | ~2560 | 矩形大节点 + 边文字 |

**线搜索接受判据**（`solver.ts`）：有位移的步必须**严格降能**；能量
容差相等只对「无力可施、位置未动」的确认步成立。若放宽为"能量不升
即接受"，在不连续的能量平台（如离散碰撞判定边界两侧）会形成「移过去
/ 移回来」的 2 周期极限环——位移停滞、力残差、回溯触底三条收敛出口
同时失守，布局永久空转不收敛（实测：2 节点长文字撑边用例）。退化到
平台时由回溯触底路径（`floorHits`）判定收敛，位置停在平台内。

## 5. 生命周期

- `step()` / `run()`：推进微调；`run()` 末尾做坐标系修正并返回
  `{ iterations, converged, energy }`；
- `refresh(options)`：参数更新 → 原地更新 `params`/ctx 开关/hopScale，
  保留当前坐标继续微调（demo 实时调参）；
- `rebuild()`：图结构变化 → 重新派生参数 + **重跑粗布局** + 新求解器；
- `invalidate()`：外部挪动节点后重算力场；
- `forceSnapshot(accuracy)`：测试钩子（同 force 策略）。

## 6. 参数与纯度

- 消费 `naturalLength`（格子与间隙的长度标尺）、力学全家桶
  （accuracy/gravity/交叉/避让……，直接透传给复用引擎）、
  `coordinateSystem`；
- **不消费分组语义**：`subgraphs` 容器作为普通大节点参与布局；
  `hiddenGroups` 声明被完全忽略（有与无声明逐位一致的纯度用例）。
  分组支持等 force-group 重写后再议；
- `seed` 当前只影响 placed 反算的确定性（无随机放置）。

## 7. 验收测试（tests/force-undirected.test.ts）

1. 确定性：同 seed 两次布局逐位一致；
2. n=100 随机图：收敛、无 NaN、无重叠；
3. 树 21：默认预算内收敛 + 全树零线段交叉（树可平面，任何交叉都说明
   叶子挂错侧）；
4. 星形 K1,12：插行列不死锁、无重叠；
5. 孤立点不堆叠；hiddenGroups 纯度；
6. mermaid 用户样本：连线零穿节点 + 渲染 `output/mermaid-undirected.svg`；
7. n=2000 压测：barnes-hut 精度 + 限步预算，全链路不崩、无重叠保持。

## 8. 性能特征与已知边界

- **粗布局本身极快**：n=2000 构造（含粗布局 + 引擎装配）约 0.5s；
- **耗时大头在微调**，且是共享引擎的成本：`RelaxationSolver` 的回溯
  线搜索每步最多 9 次力场求值（快速阶段约 2 次），叠加 exact 精度的
  O(n²) 全对计算。n=2000 exact 全程收敛约 8 分钟，barnes-hut 约
  4 倍快——与 force-directed 同一引擎同一量级。引擎级优化（求值
  缓存、BH 常数、大图自动降精度）属于 force 引擎的范畴，等
  force-group 重写阶段一并处理；
- 大图压测用例因此采用 barnes-hut + 限步预算（断言不崩/无重叠，
  不断言收敛），控制全量测试时长。

## 9. 派生接缝（有向算法如何优雅复用本算法）

本算法在两个层面上为派生算法预留接缝，`force-directed` 只覆写接缝、
不复制流程：

### 9.1 粗布局差异点：`CoarseHeuristics` 钩子（coarse.ts）

粗布局主流程（度数优先连通生长、环形扩搜、压实变距映射）与「放置美学」
完全解耦，四个决策点向具体算法征求意见：

| 钩子 | 职责 | 无向默认实现 |
|---|---|---|
| `anchor(v, neighbors)` | 环形扩搜的中心格 | 已放置邻居格坐标均值 |
| `score(v, gx, gy, neighbors, neighborIndices)` | 候选格评分（越小越优） | 张力 − 环周长奖励 |
| `isDeadlock(v, bestScore, min, cnt, bestCell)` | 是否触发插列 | 无空格或张力超阈值 |
| `deadlock(grid, anchor)` | 死锁解法 | 四方向最小移动插行列 |
| `placeSeed(grid, v)`（可选） | 新分量种子的落格 | 贴已放置区域右缘 |

`coarsePlacement` 的 `heuristics` 参数缺省为 `undirectedHeuristics(adjacency)`
——无向行为零回归；有向算法传入 `directedHeuristics(...)`（见
[layout-force-directed.md](./layout-force-directed.md)）。

### 9.2 流水线时机：`strategy.ts` 的 protected 接缝

`ForceUndirectedStrategy` 把构造/rebuild 流程中的两步抽为 protected
方法，派生类覆写即可注入自己的阶段，其余骨架（引擎装配、弛豫、
坐标系修正、生命周期）原样继承：

- `applyCoarsePlacement()`：粗布局时机（默认 = 无向 `coarsePlacement`）；
- `configureExtensions()`：力学扩展注入时机（默认 = 空 `extensions`；
  消费 `ForceContext.extensions.extraForces` 缝——求解器每步在基础
  力场之外调用它累加自定义力与势能，有向算法用它注入流动势能）。

`rebuild()` 末尾会**重新调用这两个接缝**：派生扩展闭包捕获的边下标
快照在图结构变化后会过期，重注入保证快照与图同步。

> 构造期约束：两个接缝都在基类构造函数内被调用，此时子类字段初始化器
> 尚未执行——覆写实现必须就地计算，不得依赖子类实例字段。

### 9.3 修复接缝时发现的共享缺陷

派生实现压测暴露了 `insertLine` 的一个潜伏 bug：推开后返回「锚点 +
推挤方向」的相邻格——那恰是锚点占用者的新位置，写回时会把已放置节点
从占用表覆盖掉（格还在 `posOf` 里、却不在 `grid.occ` 里，坐标永远停在
初值）。无向图死锁路径极少触发所以长期未暴露；有向层级行拥堵时插列
频繁，必然踩中。已修复为返回推开后真正空出的锚点格。
